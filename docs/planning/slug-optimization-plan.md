# Slug System Optimization Plan (Idealo Style)

## Problem

Current slugs are based on "Brand-Model-ParentSuffix". This relies heavily on fuzzy matching and keyword resolution (`findProductByParentAsinSuffix`), which is error-prone (collisions between "Pro" vs "Pro Max", "S24" vs "S24 Ultra").

## Proposed Solution: ID-Based Slugs

Adopting the Idealo/Amazon style pattern where the unique identifier is embedded in the URL.

**Format**: `/p/[ID]_-([slug-text])`
**Example**: `/p/90012345_-apple-iphone-17-pro`

### Benefits

1.  **Deterministic Resolution**: We extract the ID (`90012345`) and look it up directly. No more fuzzy matching, suffix collisions, or database LIKE queries.
2.  **Robustness**: The text part (`apple-iphone-17-pro`) becomes purely decorative (for SEO). Even if we change the title logic, old links still work as long as the ID is valid.
3.  **Performance**: Lookup by Primary Key (ID) is instantaneous compared to complex substring/regex searches.

### Implementation Steps

1.  **URL Generation (`product-families.ts`)**:
    - Update `getFamilyIdentity` to return the synthetic/real ID alongside the clean slug text.
    - Construct the final slug format: `${id}_-${text}`.

2.  **Routing (`src/app/p/[slug]/page.tsx`)**:
    - Add a regex check at the start of resolution.
    - `const match = slug.match(/^(\d+}_-/);`
    - If match found, extract ID.
    - If ID > 900M -> Treat as Synthetic Parent (force Hub View).
    - If ID < 900M -> Treat as child variant.
    - Fallback to legacy resolution if no ID found (backward compatibility).

3.  **Component Updates**:
    - Update `ProductVariantSelector` to generate links using the new format.
    - Update SEO canonical tags to prefer the new format.

### Migration Strategy

- Keep legacy routes active (`findProductByParentAsinSuffix`) indefinitely but mark them with `canonical` tags pointing to the new ID-based URL.
- New links generated by the app will use the ID format immediately.
